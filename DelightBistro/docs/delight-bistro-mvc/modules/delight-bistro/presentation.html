Слайд 01

Сеть ресторанов DelightBistro

DelightBistro — учебная модель сети кафе и бистро с акцентом на чайную карту, конструктор блюд и работу персонала в реальном времени.

Концепция Гостевой зал и кухня в одном digital-контуре: меню по типам, ингредиенты, сборка блюд, заказы, чат смены, статистика продаж.
Чай как отдельный продукт Каталог напитков вынесен в отдельный сервис (API) — как будто центральный «чайный склад» сети, к которому подключаются витрины (сайт MVC и React-приложение).
Зачем сеть Одна логика меню и заказов для точки; общий каталог чая для всех клиентских приложений; уведомления и чат для персонала филиала.
Учебный статус Pet-project на ASP.NET Core 8 + React: демонстрирует слои, auth, SignalR, кэширование Memory/Redis/OutputCache.

Слайд 02

Бизнес-цели и сценарии

Для гостя

  • Смотреть меню и типы блюд на сайте филиала
  • Оформлять заказ (авторизованный пользователь)
  • Изучать чайную карту (страница MVC или React SPA)

Для персонала и модераторов

  • Создавать меню, ингредиенты, собирать блюда
  • Вести чат смены (SignalR)
  • Смотреть статистику, выгружать CSV
  • Получать уведомления о событиях

Для разработки / DevOps (учебно)

  • Масштабировать чтение каталога чая через кэш
  • Переключать Memory ↔ Redis без смены URL API
  • Держать два клиента (Razor JS и React) на одном контракте API

Архитектура решения

ЧастьПуть / портРоль в сети
DelightBistroMvc :7284 Сайт филиала: меню, заказы, auth, чат
DelightBistroMinimalApi :7090 Центральный каталог чая + кэш
react-delight-bistro-app Vite / React 19 Отдельная витрина напитков
DelightBistroMvc.Data EF Core БД ресторана
DelightBistro.Services Serilog Общее логирование API
Браузер (гость / персонал) ├─ https://localhost:7284 → MVC → БД WebNet23Online │ └─ drink.js ───────→ API :7090 → БД WebNet23Tea └─ React SPA ────────────→ API :7090 → БД WebNet23Tea
Важно
Сервер MVC не вызывает API через HttpClient. К API ходит браузер (нужен CORS). Это имитация «витрина ↔ общий сервис каталога».

Слайд 07

Данные — две базы под сеть

DelightBistroMvc.Data · WebContext Филиал: пользователи, меню, блюда, ингредиенты, заказы, уведомления.
WebNet23Tea · MiniDbContext Общий каталог: Drink + таблица логов Serilog (Logging.SeriLogs).

Разделение учебное: «операционка ресторана» и «центральный каталог чая» как у сети с общим меню напитков и локальными заказами.

Слайд 08

Кэширование каталога

Чтобы витрины (MVC + React) не били в БД на каждый просмотр карты.

СлойГдеИнвалидация
HTTP Cache-Control ResponseHeaderMiddleware max-age=10
Output Cache .CacheOutput + теги EvictByTagAsync
Application IDrinksCacheService Remove ключей drink:all / drink:id
Memory Один процесс API — удобно для локальной разработки.
Redis Общий кэш между инстансами API (префикс DelightBistro_).

Слайд 10

Ревью и риски

Сильные стороны

  • Понятное разделение: филиал (MVC) / каталог (API) / витрина (React)
  • Кэш через интерфейс и конфиг Provider
  • SignalR для операций смены
  • Не кэшировать «пустые» ответы; NotFound по id

Что улучшить

ПриоритетНаходка
Высокий Update/Delete: Evict по тегу CacheTags.DRINK, не по строке ключа Output Cache
